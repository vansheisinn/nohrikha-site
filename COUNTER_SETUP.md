# Собственный счётчик Nohrikha

Подготовлен 19 октября 2026 г. Рабочий вариант — **Cloudflare Workers + D1**. Регистрация Deno у владельца вернула `403 SIGNUP_UNAVAILABLE`; Deno-вариант не развёрнут и доступен в истории Git. Сайт остаётся на GitHub Pages, DNS не меняется. Посещения собираются на всех 10 страницах. По обновлённому решению владельца статистика выводится только внизу RU/EN страниц контактов: текст совпадает с цветом фона и читается при выделении. Нажатие на строку раскрывает неделю по дням и источники за 30 дней; для чтения подробностей также выделить текст.

Владелец установил сервер и 19 октября подтвердил ответы `/health` → `{"ok":true}` и `/stats` → корректные нулевые агрегаты. Подключение объединено в PR №20; владелец подтвердил работу счётчика на сайте. `counter-config.js` указывает на этот Worker. Изменение вывода статистики подготовлено отдельно для ручного слияния. При пустом `endpoint` запросов к сборщику, записи даты и счётчика нет.

## Однократная настройка через кабинет

1. В Worker **Bindings → Add binding → D1 database** задать имя **DB** и выбрать `nohrikha-counter`, сохранить. Регистр `DB` важен.
2. В Worker **Settings → Variables and Secrets** добавить тип **Secret**, имя **COUNTER_SIGNING_KEY**, значение — случайный пароль не короче 32 байт (например, 48 случайных латинских букв/цифр из менеджера паролей). Сохранить у себя; значение в чат и репозиторий не присылать. `MAX_DAILY_VIEWS` необязателен: по умолчанию 5000.
3. В **Edit code** заменить исходный Hello World готовым содержимым `counter/worker.bundle.js` и нажать **Deploy**. Это обычный ES-модуль без импортов; npm в кабинете не требуется. Файл автоматически собирается из проверенных исходников командой `npm run bundle`. Тест проверяет соответствие сборки исходникам и запускает именно этот код в workerd с настоящим локальным D1.
4. Таблицы создаются автоматически при первом запросе, после проверки серверного секрета. Пакет SQL из `counter/schema.ts` атомарен, использует `IF NOT EXISTS` и `INSERT OR IGNORE`, не удаляет и не обнуляет существующие числа. SQL вручную выполнять не требуется.
5. В **Settings → Observability** отключить постоянные Workers Logs и Traces, если включены. Приложение само не пишет журналы. При развёртывании через Wrangler в конфигурации уже задано `observability.enabled: false`; при вставке JS через редактор эта настройка файла не применяется автоматически.
6. Проверить `https://nohrikha-counter.vansheisinn.workers.dev/health` → `{"ok":true}` и `/stats` → JSON с числами. Проверить Workers Free в кабинете, доступ из нужных сетей и расход квот. `Hello World` означает, что наш код ещё не установлен; `503` — что не готовы секрет или привязка либо не удалось открыть базу.
7. После рабочей проверки Codex назначает реальный endpoint и обновляет версии ресурсов на 10 страницах. Подключение из `feat/simple-visitor-counter` объединено владельцем в PR №20. После обновления отображения открыть страницу контактов, выделить текст внизу и нажать строку статистики для подробностей. Обновление данных может занять до минуты. Повторная загрузка любой страницы добавляет просмотр, но не нового браузера в этот день. Не отправлять искусственные просмотры в рабочую базу из автоматических проверок.

При необходимости можно позже подключить GitHub Builds вместо ручного редактора: репозиторий `vansheisinn/nohrikha-site`, папка `counter`, установка `npm ci`, проверка `npm run check`, deploy `npm run deploy`. Права аккаунта и CI на D1 проверяются отдельно. Простое слияние PR для GitHub Pages само не обновляет вручную установленный сервер Cloudflare.

## Бесплатные лимиты

По официальной документации, проверенной 19.10.2026:

| Ресурс Free | Лимит |
| --- | --- |
| Workers | 100 000 запросов/сутки, 10 мс CPU на вызов |
| D1 — прочитанные строки | 5 000 000/сутки |
| D1 — записанные строки | 100 000/сутки |
| D1 — объём | 5 ГБ на аккаунт, до 500 МБ на одну базу |

Квоты общие для аккаунта; счётчик не единственный потребитель, если в аккаунте есть другие приложения. На Free при превышении запросов/чтений/записей сервис возвращает ошибки до сброса квот, вместо платного превышения. Карту, Workers Paid, платные дополнения и повышение тарифа не подключаем. При изменении условий сначала свериться с кабинетом.

При нашем пределе 5000 принятых просмотров/день — порядка 15 000 HTTP-запросов от штатного скрипта и порядка 10–20 тысяч изменённых строк D1 (включая общий итог и индексы). Чтения статистики кешируются до минуты; нагрузку добавляют боты и непринятые запросы. Это оценка, не гарантия расхода: после запуска проверить реальную статистику ресурсов и CPU. Дневной предел приложения не ограничивает все входящие запросы к платформе.

Источники: [Workers pricing](https://developers.cloudflare.com/workers/platform/pricing/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), [D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

## Что считается

- **Посетители сегодня** — приблизительное число браузеров, впервые учтённых за московские календарные сутки. RU/EN имеют общий ключ `nohrikha.counter.lastDay`; его единственное значение — дата `YYYY-MM-DD`, без идентификатора. Очистка хранилища, другое устройство и инкогнито могут увеличить оценку. При недоступном localStorage считаются только просмотры. Для современных браузеров Web Locks согласуют вкладки; в старых браузерах остаётся приближённый подсчёт.
- **Всего просмотров** — открытия страниц с момента включения. Перезагрузка и восстановление из истории добавляют просмотр; переход к якорю, смена видимости вкладки и предварительно загруженная скрытая страница — нет. Скрытая страница считается после показа. Старые посещения восстановить нельзя.
- **Источники** относятся к первому учтённому заходу браузера за день. Скрипт на устройстве переводит referrer или `utm_source` в один из восьми фиксированных классов: Google, Яндекс, Bing, Telegram, WhatsApp, социальные сети, другие сайты, прямые/неизвестно. Полный URL, параметры, запрос поиска и имя произвольного сайта не отправляются.
- Статистика кешируется до минуты. На странице контактов она загружается независимо от отправки просмотра: медленная запись не задерживает чтение чисел. Клиент ждёт ответ до 10 секунд; сайт и форма работают во время ожидания. В блоке цветом фона при выделении видны состояния «Загрузка статистики…» и «Статистика временно недоступна.». Ошибка не подменяет отсутствующие данные нулями; ранее показанные числа сохраняются при неудачном обновлении. Лимит за день отмечается в раскрытом блоке. Отказ сервера, блокировщик, отсутствие JavaScript и ошибки сети дают недосчёт, а не поломку сайта.

Для ссылок в собственном канале и сообщениях:

- Telegram: `https://nohrikha.com/?utm_source=telegram`
- WhatsApp: `https://nohrikha.com/?utm_source=whatsapp`

Без метки мессенджер часто не передаёт источник. Счётчик не может восстановить его по обычной скопированной ссылке. Метки не меняют canonical страниц.

## Данные и защита

В D1 только наши таблицы `daily` (ключ — московская дата, числовые views/browsers и восемь числовых групп источников) и `totals` (одна общая сумма). Нет IP, их хешей, UA, fingerprint, постоянных идентификаторов, сырых событий или полных referrer/URL. Cloudflare как хостер обрабатывает сетевые подключения и технические данные; отсутствие персональных данных в нашей базе не означает их отсутствия у провайдера.

Принятый просмотр выполняет один параметризованный UPSERT. Триггер меняет общий итог в той же транзакции; условие `daily.views < limit` проверяет общий предел даже при запросах из разных экземпляров. Имена колонок берутся только из фиксированного списка; посетительские данные привязываются параметрами.

`GET /challenge` выдаёт московскую дату и HMAC-талон на 90 секунд. `POST /collect` принимает только талон, boolean первого захода и фиксированный класс источника. Тело не более 512 байт, ожидание чтения до двух секунд. Талон не является идентификатором браузера и не хранится в D1. `fetch` не передаёт cookies и Referer. Сервер проверяет точный Origin, подпись, срок, метод и поля. Кеш использованных талонов ограничен и живёт только в RAM; частота запросов ограничивается на экземпляр. Неопределённые результаты не повторяются автоматически, чтобы не создавать накрутку.

**Граница защиты:** CORS не является авторизацией. Поддельный Origin, новые талоны, несколько экземпляров и перезапуски не позволяют гарантировать защиту от целенаправленной накрутки. Для строгой глобальной дедупликации пришлось бы хранить дополнительные события/идентификаторы. Эта версия ограничивает простые дубли и расход, не обещает точное число людей.

`/stats` публичен. Серверных методов сброса, редактирования или удаления нет. Git/ZIP сохраняет исходники, но не D1. `/stats` — снимок недели, источников за 30 дней и общей суммы, не полный архив. У Free D1 есть Time Travel на 7 дней; перед изменениями схемы отдельно экспортировать базу средствами Cloudflare.

Доступ `workers.dev` из России и других стран нельзя считать гарантированным: проверять реальные сети. Недоступный счётчик даст недосчёт этой аудитории; основной сайт на GitHub Pages продолжит работать.

## Локальная проверка и отключение

Node.js 22+ (проверено на 24), npm. Версии инструментов закреплены в `counter/package-lock.json`; runtime-код не имеет внешних библиотек:

```sh
npm ci --prefix counter
npm --prefix counter run check
npm --prefix counter test
npm --prefix counter run bundle
python3 checks/check_counter_browser.py
python3 checks/check_site.py
python3 checks/check_editorial.py
python3 scripts/build_play.py --check
```

Серверные тесты запускают настоящий workerd с локальным D1 через Miniflare; облачные данные не меняются. Браузерные тесты используют Playwright/Chromium и подменяют сборщик; письма и рабочие просмотры не отправляются.

Для локального сервера создать игнорируемый `counter/.dev.vars` с только тестовым `COUNTER_SIGNING_KEY` (от 32 байт), выполнить `npm run dev` из `counter`; локальные таблицы создадутся автоматически. Рабочий секрет не копировать. `--remote` при локальных проверках не использовать.

Чтобы отключить сбор, оставить `endpoint: ''` и обновить версии ресурсов в HTML. Подключение и отключение — через проверенную ветку и ручное слияние владельцем после бэкапа; DNS не меняется.
