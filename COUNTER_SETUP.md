# Собственный счётчик Nohrikha

Подготовлен 19 октября 2026 г. Код ещё не подключён к действующему сборщику: `endpoint` в `counter-config.js` пуст. При таком состоянии нет запросов к Deno, записи даты в браузере и видимого счётчика. Слияние этой подготовительной ветки само по себе не запускает сбор статистики.

По решению владельца статистика публичная: компактная строка внизу каждой страницы раскрывает посещения за неделю и источники за последние 30 дней. Отдельный аккаунт аналитики, кабинет и пароль для просмотра не нужны. Главный сайт остаётся на GitHub Pages, DNS менять не требуется.

## Однократный запуск владельцем

1. Войти через GitHub в **новый** [Deno Deploy](https://console.deno.com/). Проверить Free без карты: доступны ли приложение и Deno KV, какие квоты действуют и что происходит при их исчерпании. Платный тариф, карту и автоматические списания не подключать. Если без них запуск невозможен — остановиться; код пока остаётся отключённым.
2. Создать приложение из репозитория `vansheisinn/nohrikha-site`, предоставив доступ только к нужному репозиторию. Для первоначальной проверки выбрать ветку со счётчиком. Рабочая папка приложения — `counter`, команда запуска — `deno task start`, отдельная сборка не требуется. После слияния проверенной версии переключить источник на `main`.
3. В разделе Databases создать Deno KV и назначить приложению. Это отдельная база; сайт и Formspree не затрагиваются. Используется `Deno.openKv()` без вручную выданного клиенту токена. Проверить назначение базы production-окружению; тестовые окружения могут иметь отдельные базы.
4. Добавить один серверный секрет `COUNTER_SIGNING_KEY`: случайное значение не короче 32 байт, например пароль из 48 случайных латинских букв/цифр. Сохранить у себя. Значение не присылать в чат, не вставлять в код и GitHub. Это подпись короткоживущих запросов, а не пароль посетителя. `COUNTER_KV_PATH` на Deploy **не задавать**. Необязательный `MAX_DAILY_VIEWS` имеет значение 5000 по умолчанию.
5. После запуска передать Codex **публичный адрес приложения**, вида `https://nohrikha-counter.<организация>.deno.net`. Он не является секретом. Проверить `/health` и `/stats`; проверить доступ из нужных сетей и расход бесплатных квот. Работа из одной сети не гарантирует доступность из России или всех других стран.
6. Codex вставляет адрес в `counter-config.js`, обновляет версии локальных ресурсов во всех 10 страницах и проверяет реальное подключение в отдельной ветке. Владелец вручную создаёт и сливает PR. После обновления Pages проверить, что число просмотров меняется, а повторная загрузка в этот день не добавляет нового браузера.

Текущие численные квоты нового Deploy Free/KV из этой среды не подтверждены. Старые квоты Deploy Classic не использовать: Classic закрыт. До сверки кабинета запуск как гарантированно бесплатный не заявляется. В документации нового Deploy описаны сокращённые квоты без привязки карты и приостановка Free-приложения при превышении лимитов; актуальные условия нужно проверить до запуска: [тарифы](https://deno.com/deploy/pricing), [официальный changelog](https://docs.deno.com/deploy/changelog/#september-26th-2025), [KV](https://docs.deno.com/deploy/reference/deno_kv/).

## Что считается

- **Посетители сегодня** — приблизительное число браузеров, впервые учтённых за московские календарные сутки. RU/EN имеют общий ключ `nohrikha.counter.lastDay`; его единственное значение — дата `YYYY-MM-DD`, без идентификатора. Очистка хранилища, другое устройство и инкогнито могут увеличить оценку. При недоступном localStorage считаются только просмотры. Для современных браузеров Web Locks согласуют вкладки; в старых браузерах остаётся приближённый подсчёт.
- **Всего просмотров** — открытия страниц с момента включения. Перезагрузка и восстановление из истории добавляют просмотр; переход к якорю, смена видимости вкладки и предварительно загруженная скрытая страница — нет. Скрытая страница считается после показа. Старые посещения восстановить нельзя.
- **Источники** относятся к первому учтённому заходу браузера за день. Скрипт на устройстве переводит referrer или `utm_source` в один из восьми фиксированных классов: Google, Яндекс, Bing, Telegram, WhatsApp, социальные сети, другие сайты, прямые/неизвестно. Полный URL, параметры, запрос поиска и имя произвольного сайта не отправляются.
- Статистика кешируется до минуты. Лимит за день отмечается в раскрытом блоке. Отказ сервера, блокировщик, отсутствие JavaScript и ошибки сети дают недосчёт, а не поломку сайта.

Для ссылок в собственном канале и сообщениях:

- Telegram: `https://nohrikha.com/?utm_source=telegram`
- WhatsApp: `https://nohrikha.com/?utm_source=whatsapp`

Без метки мессенджер часто не передаёт источник. Счётчик не может восстановить его по обычной скопированной ссылке. Метки не меняют canonical страниц.

## Данные и защита

В KV только ключ `['totals']` со значением `{views: число}` и строки `['daily', 'YYYY-MM-DD']`:

```json
{"views": 10, "browsers": 4, "sources": {"direct": 1, "google": 1, "yandex": 0, "bing": 0, "telegram": 2, "whatsapp": 0, "social": 0, "other": 0}}
```

IP, их хеши, UA, fingerprint, идентификаторы посетителей, сырые события, адреса страниц и рефереры в KV не сохраняются. Приложение не пишет журналы запросов. Платформа Deno сама обрабатывает сетевые подключения и автоматически создаёт технические трассы; отключить всю платформенную телеметрию нельзя. Поэтому обещать отсутствие технической информации у хостера нельзя. Основной регион KV — США. [Официальная документация телеметрии](https://docs.deno.com/deploy/reference/observability/).

`GET /challenge` выдаёт серверную дату и подписанный HMAC талон на 90 секунд. `POST /collect` принимает только талон, boolean первого захода и фиксированный класс источника. Максимум 512 байт тела; ожидание тела ограничено двумя секундами. Талон не является идентификатором браузера и не записывается в KV. `fetch` не передаёт cookies и Referer. Нет отправки во внешние аналитические платформы.

Сервер проверяет точный Origin, подпись, срок талона, формат и поля. Повтор талона на одном экземпляре отсекается до записи в KV. Частота выдачи/приёма ограничена на экземпляр, дневной предел просмотров проверяется атомарно вместе с дневной и общей суммой. Запросы не повторяются автоматически при неизвестном результате, запись даты до отправки может дать недосчёт при ошибке.

**Граница защиты:** CORS не является авторизацией. Поддельный Origin, новые талоны, несколько экземпляров и перезапуски не позволяют гарантировать защиту от целенаправленной накрутки. Кеш использованных талонов находится только в RAM и не общий для всех экземпляров. Для строгой глобальной дедупликации пришлось бы хранить дополнительные события/идентификаторы, чего эта версия не делает. Дневной предел ограничивает принятые записи, но не все тарифицируемые входящие запросы; финансовую границу должен обеспечивать Free самого провайдера.

Статистика по `/stats` публична по решению владельца, серверного кабинета и пароля нет. Публичных методов сброса/редактирования/удаления нет. Бэкап Git/ZIP сохраняет исходники, но не KV: статистика — отдельные данные у Deno. `/stats` позволяет сохранить текущий JSON-снимок (неделя, источники за 30 дней, общая сумма), это не полный архив всех дневных строк.

## Локальная проверка и отключение

Нужен Deno 2.5+ с KV; внешних библиотек у сервера нет:

```sh
deno task --config counter/deno.json check
deno task --config counter/deno.json test
python3 checks/check_counter_browser.py
python3 checks/check_site.py
python3 checks/check_editorial.py
python3 scripts/build_play.py --check
```

Браузерный тест использует установленный Playwright/Chromium и подменяет сборщик; реальные посещения и письма не отправляются. Серверные тесты работают с настоящим локальным Deno KV в памяти. Пример запуска для отдельной локальной HTTP-проверки:

```sh
COUNTER_SIGNING_KEY='local-only-test-key-with-at-least-32-bytes' COUNTER_KV_PATH='/tmp/nohrikha-counter-local.sqlite' deno task --config counter/deno.json start
```

Чтобы отключить сбор, оставить `endpoint: ''` и обновить версии ресурсов в HTML. Сайт, форма, навигация и SEO продолжают работать. Подключение и отключение — через обычный бэкап, отдельную ветку и ручное слияние владельцем; DNS не меняется.
