# Контакты и подключение приёма сообщений

## Что уже подготовлено

- На каждой странице RU/EN/DE/KZ есть ссылка на канал https://t.me/nohrikha. На странице контактов канал выделен отдельно. Это канал проекта, не личный адрес и не обещание конфиденциальности.
- Форма: необязательные имя/email, обязательные сообщение и согласие, лимиты длины, поле-ловушка `_gotcha`, блокировка повторного нажатия, доступные подписи и статусы. Вложения не принимаются.
- Сообщения не сохраняются в коде, cookies или localStorage и не отправляются в GitHub Issues. Восстановление полей после Back может выполняться браузером.
- До подключения обработчика форма отключена, включая режим без JavaScript. Ложного подтверждения отправки нет.
- Подготовлен адаптер для обычного HTML POST в Formspree. Он не активирован: выбор внешнего сервиса и его условий ещё требует ответа владельца. Если выбран другой сервис, адаптер нужно заменить и повторно проверить.

## Почему защита не заканчивается JavaScript

Публичную форму можно вызвать в обход страницы. Ограничения в браузере, согласие, honeypot и защита от повторного клика помогают, но не заменяют фильтрацию, CAPTCHA и ограничения запросов у обработчика. Ни один вариант не гарантирует нулевой спам. Значение `spamProtectionVerified` — отметка выполненной ручной проверки, не серверная защита само по себе.

GitHub Pages не исполняет серверный обработчик. Для реального приёма необходим аккаунт внешнего сервиса, доступный получателю, и проверка доставки. В этой среде нет настроенного обработчика, его адреса, кабинета или связанных секретов.

## Вариант Formspree (предложен, пока не подключён)

1. Владелец согласовывает сервис, актуальные лимиты/стоимость, условия хранения и удаления обращений, обработку персональных данных. Цены и доступность функций не зафиксированы: их нужно проверить в выбранном тарифе. Автоматические оплаты и подписки не создавались.
2. Владелец создаёт форму в своём кабинете Formspree, подтверждает получателя уведомлений. Email и секреты не добавлять в публичный репозиторий или чат.
3. Для включения нужен только публичный адрес формы вида `https://formspree.io/f/<id>`. Это адрес отправки, не секретный API-ключ. Не использовать адрес с личной почтой в URL.
4. В кабинете включить доступную серверную защиту от спама и обязательную CAPTCHA/проверку человека; убедиться, что обычный POST из браузера действительно проходит эту проверку. Проверить ограничения частоты и квоты. Если выбранный тариф не обеспечивает нужную защиту, не включать форму — выбрать другой тариф или обработчик после согласования.
5. Где доступно, ограничить принимающие домены/источники: фактический GitHub Pages host `vansheisinn.github.io`, позднее только подтверждённый собственный домен. Ограничение Origin/Referer само по себе не является антиспам-защитой. DNS в этой задаче не менять.
6. В `contact-config.js` указать provider `formspree` и публичный endpoint. `enabled` и `spamProtectionVerified` оставлять false на время настройки. Если требуется тест, включать только в локальном окружении или отдельной тестовой конфигурации, а не в опубликованной ветке main.
7. Утвердить уведомление о данных/сроках хранения и проверить отсутствие обещаний абсолютной анонимности. На подключённой форме JS показывает Formspree и ссылку на политику сервиса. Нельзя оставлять устаревшее предупреждение «форма не подключена» в дополнительном блоке GitHub после активации — обновить его в том же PR с подключением.
8. Выполнить живые проверки на всех четырёх языках: успешный приём без имени/email; доставка в кабинет и уведомление получателю; CAPTCHA и отказ при её непрохождении; попытка с заполненной `_gotcha`; квота/ограничение запросов и ошибка сервиса; восстановление введённого текста после возврата. Проверить мобильную доступность CAPTCHA. Не отправлять настоящие исторические или личные материалы в тестах. Удалить тестовые записи из кабинета.
9. После проверок установить обе отметки true отдельным проверенным изменением. Согласовать PR с владельцем; не сливать самостоятельно.

При отправке посетитель переходит на страницу обработчика. Проверка человека, подтверждение приёма и ошибки показываются там. Наш сайт не показывает «Отправлено» до ответа сервиса и не обещает доставку письма только по факту перехода. На серверной ошибке нужно вернуться назад; текст не очищается нашим кодом. Если браузер его не восстановил, восстановление не гарантируется. Без JavaScript отправка намеренно отключена.

## Проверки в этой ветке

- `python3 checks/check_site.py` — внутренние ссылки и якоря, 16 страниц, noindex/hreflang, Telegram везде, недоступность неподключённой формы, необязательная идентификация, сохранность исторических материалов.
- `node --check contact.js` и `node --check contact-config.js` — синтаксис.
- `python3 checks/check_contact_browser.py` — нужен установленный Playwright и Chromium (`/usr/bin/chromium`). Изолированный локальный сервер, все внешние запросы заблокированы или подменены. 48 раскладок (1440/375/320), отсутствие JS ошибок и переполнения, валидация, выключенная конфигурация, неверные endpoints, honeypot, повторы, имитация POST/ошибки сервиса, возврат без потери черновика, отсутствие отправки без JS.

Тестовый ответ обработчика не доказывает настоящую доставку, работу CAPTCHA, реальные квоты или серверную фильтрацию. Живые проверки ещё не выполнены. Официальная документация Formspree и GitHub API из этой среды отвечали `403 Forbidden`; актуальные настройки сервиса должны быть проверены перед подключением, а не приняты на веру.

Индексация остаётся выключенной. DNS, домены и Pages не изменялись. Публикация — только через проверенный владельцем PR; если Pages настроен на main, слияние запустит развёртывание.
